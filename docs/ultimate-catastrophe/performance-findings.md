# Performance findings — 1.7.6 review candidate

The 55 ABBA windows comprise 26 current-1.7.5 pairs, ten frozen-1.7.4 ordinary/impact pairs, fifteen longer repeats covering every initially flagged CPU/GPU window, and four fixed-camera desktop impact pairs. All 220 individual runs are retained. No visual implementation changed during these measurements.

Ordinary 21-snake desktop rendering submits exactly **116 calls / 171,302 triangles** in both variants. Initial desktop CPU median/p95 is **4.20 / 6.40 → 4.20 / 6.70 ms**. The initial mobile ordinary GPU difference did not persist in the longer repeat; that repeat's CPU median/p95 is **2.05 / 3.20 → 1.90 / 3.10 ms**, with identical ordinary calls/triangles. This is evidence of unchanged ordinary rendering work, not a claim that every timing sample is identical.

Kitsu and Shiro's initial desktop impact CPU flags did not reproduce in longer same-camera samples. Kairo/Pomu desktop impact and aftermath costs do reproduce. The largest same-camera desktop CPU result is Pomu impact: **7.00 / 10.45 → 9.70 / 14.60 ms** (+38.6% median / +39.7% p95). GPU median changes **10.43 → 10.73 ms** (+2.8%), while render-interval median changes **13.60 → 12.85 ms**; render-interval p95 increases slightly, **16.80 → 17.10 ms**. It would be inaccurate to report zero regression.

Kairo impact CPU is **6.70 / 9.75 → 8.20 / 12.25 ms**; GPU median is **9.58 → 10.42 ms**, and render-interval median is **12.95 → 12.45 ms**. Its aftermath replaces an expensive legacy cloud/ray shell: GPU median improves **13.39 → 9.72 ms**, and render-interval median **16.50 → 12.00 ms**, despite CPU median rising **6.55 → 8.30 ms**. Pomu aftermath similarly improves GPU/render-interval medians while increasing measured CPU time. CPU submission and environment-culling portions account for most of the measured desktop CPU difference; the effect-update portion stays approximately 0.3–0.35 ms. Driver scheduling is a possible contributor, but these measurements do not prove a single cause.

Fixed-camera pairs show that the remaining cost is not explained entirely by new framing. Kairo impact CPU median rises **3.95 → 5.00 ms**, and Pomu **4.00 → 4.95 ms**. Their GPU medians change **+4.1% / -5.5%**, with render-interval medians improving **6.1% / 11.1%**. Kitsu improves and Shiro stays at CPU median parity in these fixed-camera pairs. The new effect draws remain bounded; lower draw counts alone do not guarantee lower CPU submission time.

The phone-width Shiro charge adds one shared gathering draw and records a repeatable CPU cost: **1.80 / 2.75 → 2.95 / 4.20 ms** (+1.15 ms median). GPU median changes approximately **+10.1%**; sampled render intervals remain approximately **6.9 ms**, limited by this desktop host's browser cadence. Shiro mobile aftermath records **2.55 / 3.75 → 3.00 / 4.30 ms**, while its GPU median improves 10.6%. Kitsu mobile charge's GPU median rises 18.6%, with CPU median only **3.30 → 3.45 ms**, GPU p95 +3.1%, and unchanged sampled frame cadence. These results describe Intel Iris Xe at a phone-sized viewport, not physical-phone hardware.

The stronger bounded impact and longer aftermath are retained as the candidate's deliberate visual cost. Redundant legacy layers and update loops are suppressed, production removes eight independently owned pressure materials in favor of four shared materials, no blast geometry is rebuilt during frames, and all effect draw/triangle caps pass. Ordinary play has no additional submitted effect draws. A further density reduction would change the proposed visual result; promotion awaits visual approval with these costs disclosed.

Held benchmarks retain all 21 snakes after the nominal wipe for comparable stress. Actual live recordings eliminate all 20 opponents on the original beat; during 3.65–4.40 seconds their average total scene calls fall from **103.4 → 97.0** for desktop Kitsu, **76.5 → 72.0** for Kairo, **75.8 → 66.0** for Shiro, and **86.5 → 83.0** for Pomu. These recorded live counts are not matched CPU benchmarks and do not replace the stress results above.

The source report includes every original, repeated, older-baseline and fixed-camera table, resource counts, effect peaks and raw timing distributions. Sparse asynchronous GPU queries and Windows host variance limit attribution. No sustained FPS or physical-phone thermal/touch claim is made.
